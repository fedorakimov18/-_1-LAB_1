## Задача 1

Нужно поменять местами значения переменных a и b, но нельзя заводить третью
переменную, разрешены только присваивание и арифметика.

Обычно такое делают через временную переменную, но тут так нельзя, поэтому я
использовал сумму. Смысл в том, что если сложить a и b, то в этой сумме как бы
лежат оба числа сразу, и любое из них можно достать обратно, вычтя другое.

Сначала пишем a = a + b, теперь в a сумма. Дальше b = a - b, то есть из суммы
вычитаем старое b и получаем старое a — записали его в b. И последним шагом
a = a - b, где b уже новое, поэтому из суммы вычитается старое a и в a остаётся
старое b. Обмен закончен.

Проверял на числах из условия: вводил a = 4 и b = 5, после работы программы
получилось a = 5 и b = 4, то есть всё правильно.

Тут важен порядок действий, если строчки переставить, ничего не получится,
потому что на третьем шаге используется уже новое значение b.
Ещё нужно понимать, что если числа очень большие, их сумма может не влезть в int
и будет переполнение, но для нашей задачи это неважно.

## Задача 2

Надо за один цикл посчитать F(n) = 1! * 2! * 3! * ... * n!.

Первое, что приходит в голову — сделать два цикла: внешний идёт по i, а
внутренний каждый раз заново считает i!. Но по условию цикл должен быть один, да
и считать одно и то же по кругу бессмысленно.

Я сделал по-другому. Если присмотреться, то каждый следующий факториал получается
из предыдущего простым умножением: i! это (i-1)! умножить на i. Значит, не надо
его пересчитывать заново, достаточно запомнить предыдущий факториал в переменной
и домножить его на i.

Поэтому в программе две переменные, которые накапливают значения. В factorial
хранится текущий факториал, а в result — сам ответ. На каждом шаге цикла я
сначала домножаю factorial на i (и получаю i!), а потом сразу домножаю result на
этот factorial. За один проход цикла делается и то, и другое.

Посмотрим, как это работает при n = 4. На первом шаге factorial = 1 (это 1!) и
result тоже 1. На втором шаге factorial становится 2 (это 2!), result = 1 * 2 = 2.
На третьем factorial = 6 (это 3!), result = 2 * 6 = 12. На четвёртом factorial = 24
(это 4!), result = 12 * 24 = 288. Получили 288, что и требовалось.

Цикл выполняется ровно n раз, то есть сложность линейная.

Числа тут растут очень быстро, поэтому я взял тип unsigned long long, обычного
int хватило бы только до n = 6. С unsigned long long программа правильно считает
до n = 8, там получается 5056584744960000. При n = 9 в ответе уже 22 цифры, такое
число не помещается ни в один стандартный целый тип C++, и результат будет
неверным из-за переполнения.

## Задача 3

Дан блок, где если A = 0, то B = 2, иначе B = 1. Известно, что A бывает только 0
или 1. Нужно убрать условный оператор, причём тернарный оператор тоже нельзя.

Раз у A всего два возможных значения, я просто выписал оба случая: при A = 0
нужно получить B = 2, а при A = 1 нужно получить B = 1. Видно, что когда A
увеличивается на единицу, B на единицу уменьшается, то есть зависимость линейная
и её можно записать как B = k * A + c.

Дальше подставляем. При A = 0 формула даёт B = c, а нам нужно 2, значит c = 2.
При A = 1 получается B = k + 2, а нужно 1, значит k = -1. Итого выходит
B = -A + 2, или, что то же самое, B = 2 - A.

Проверяем оба варианта: при A = 0 получаем 2 - 0 = 2, при A = 1 получаем
2 - 1 = 1. Всё совпадает с исходным блоком, а никакого условия в коде нет.

Мне кажется, главный вывод этой задачи в том, что если переменная принимает мало
значений, то выбор часто можно заменить обычной арифметикой.
